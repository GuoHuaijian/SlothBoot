## 1. 模型类型边界

### 1.1 四种模型类型定义

| 类型 | 后缀 | 所在层 | 职责 | 继承 |
|------|------|--------|------|------|
| **Entity** | 无特定后缀 | Mapper/Service 层 | 数据库表映射，含持久化字段 | `BaseEntity` |
| **DTO** | `DTO` 或 `Request`/`Command` | Controller 入参 | 数据传输对象，跨层传递数据 | `BaseDTO`（可选） |
| **VO** | `VO` 或 `Response` | Controller 出参 | 视图对象，返回给前端的数据 | `BaseVO`（可选） |
| **Query** | `Query` | Service/Controller | 查询条件封装 | `BaseQuery` |

### 1.2 使用规则

| 规则 | 说明 |
|------|------|
| Entity **禁止**直接返回前端 | 必须转换为 VO 后返回 |
| DTO **禁止**直接传入 Mapper | 必须转换为 Entity 后持久化 |
| VO **禁止**包含敏感字段 | 如密码、密钥、内部 ID（按需） |
| DTO 和 VO **可以**共用 | 简单场景下 DTO 和 VO 可合并为一个类 |
| 类型转换使用 MapStruct | 禁止手动 BeanUtils.copyProperties（除非简单场景） |

### 1.3 命名示例

```
Entity:  User, Order, Product
DTO:     UserDTO, LoginRequest, OrderCreateRequest, ProductUpdateCommand
VO:      UserVO, LoginResponse, OrderVO
Query:   UserQuery, OrderPageQuery
```

### 1.4 字段约束

| 类型 | id | createTime | updateTime | createBy | updateBy | deleted | version | 密码/密钥 |
|------|:--:|:----------:|:----------:|:--------:|:--------:|:-------:|:-------:|:---------:|
| Entity | 必有 | 必有 | 必有 | 必有 | 必有 | 必有 | 可选 | 按需 |
| DTO | 无 | 无 | 无 | 框架填充 | 框架填充 | 无 | 无 | **禁止** |
| VO | 按需 | 按需 | 按需 | 按需 | 按需 | 无 | 无 | **禁止** |
| Query | 可选 | 可选范围 | 无 | 无 | 无 | 无 | 无 | 无 |

## 2. 异常体系规范

### 2.1 异常层次（目标状态）

```
RuntimeException
  └── BaseException（携带 ErrorCode）
        ├── BizException      — 业务异常（可预期，WARN 级别）
        ├── SystemException   — 系统异常（不可预期，ERROR 级别）
        └── RemoteCallException — 远程调用异常（携带 serviceName + url）
              ├── RemoteServiceNotFoundException
              └── RemoteRateLimitException
```

### 2.2 ErrorCode 体系

```
ErrorCode（接口：getCode() + getMsg()）
  ├── GlobalErrorCode（枚举：全局错误码 0-999）
  ├── SimpleErrorCode（record：动态错误码）
  └── 各模块 ErrorCode（枚举：如 AiErrorCode）
```

### 2.3 错误码分配规范

| 区间 | 归属 | 说明 |
|------|------|------|
| 0 | 成功 | `GlobalErrorCode.SUCCESS` |
| 1-999 | 全局 | `GlobalErrorCode`（400/401/403/404/429/500 等） |
| 1000-1899 | 保留 | 预留给未来全局错误码 |
| 1900-1999 | Web | `starter-web` 模块 |
| 2000-2099 | AI | `starter-ai` 模块 |
| 2100-2199 | Redis | `starter-redis` 模块 |
| ... | ... | 详见 `docs/error-code-registry.md` |

### 2.4 异常使用规范

| 场景 | 使用异常 | 日志级别 | 示例 |
|------|----------|----------|------|
| 业务规则不满足 | `BizException` | WARN | 用户名已存在、余额不足 |
| 参数校验失败 | `BizException` 或 ValidationException | WARN | 手机号格式错误 |
| 系统内部错误 | `SystemException` | ERROR | 数据库连接失败、NPE |
| 远程服务调用失败 | `RemoteCallException` | ERROR | Feign 调用超时 |
| 权限不足 | `BizException(FORBIDDEN)` | WARN | 无权访问 |

### 2.5 异常创建方式

```java
// 方式 1: 使用 ErrorCode 枚举
throw new BizException(GlobalErrorCode.NOT_FOUND);

// 方式 2: 使用 ErrorCode + 自定义消息
throw new BizException(GlobalErrorCode.BAD_REQUEST, "用户名不能为空");

// 方式 3: 使用 SimpleErrorCode（动态场景）
throw new RemoteCallException("order-service",
    new SimpleErrorCode(503, "Service Unavailable"), "远程调用失败");

// 禁止: 直接 new RuntimeException
// 禁止: throw new Exception("出错了")  — 不携带 ErrorCode
```

### 2.6 异常日志规范

```java
// 业务异常（WARN）— 不打印堆栈
log.warn("[Biz] 业务异常: code={}, msg={}", ex.getCode(), ex.getMessage());

// 系统异常（ERROR）— 必须打印堆栈
log.error("[System] 系统异常: code={}", ex.getCode(), ex);

// 远程调用异常（ERROR）— 包含服务名和 URL
log.error("[Remote] 远程调用异常: service={}, url={}, msg={}",
    ex.getServiceName(), ex.getUrl(), ex.getMessage(), ex);
```

## 3. 统一响应规范

### 3.1 R\<T> 结构

```json
{
  "code": 0,
  "msg": "success",
  "data": { ... },
  "traceId": "abc123",
  "timestamp": 1716864000000
}
```

### 3.2 使用规则

| 场景 | 响应 |
|------|------|
| 成功 | `R.ok(data)` |
| 成功（无数据） | `R.ok()` |
| 业务失败 | `R.fail(errorCode)` |
| 分页数据 | `R.ok(pageResult)` |
