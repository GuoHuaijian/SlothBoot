# 注释与文档规范

> 版本: v1.0 | 制定日期: 2026-05-27 | 阶段: Day 3
> 本文档为 SlothBoot 全项目强制注释和文档规范。

---

## 1. 总原则

| 原则 | 说明 |
|------|------|
| 代码自解释优先 | 好的命名胜过注释，先优化命名再考虑加注释 |
| 注释说明 WHY，不说明 WHAT | 代码本身说明"做什么"，注释说明"为什么这样做" |
| 公开 API 必须有 Javadoc | 所有 `public` 类、接口、方法必须有 Javadoc |
| 内部实现按需注释 | 仅在逻辑复杂、非直觉、有坑时加注释 |
| 禁止无意义注释 | 禁止 `// 获取名称` 这种重复代码含义的注释 |

## 2. 类注释规范

### 2.1 必须有 Javadoc 的类型

- 所有 `public class` / `public interface` / `public enum` / `public abstract class`
- 所有 `@ConfigurationProperties` 类
- 所有 `@AutoConfiguration` 类
- 所有 `@FunctionalInterface`

### 2.2 类注释模板

```java
/**
 * [一句话描述类的职责]。
 * <p>
 * [可选：补充说明设计意图、使用场景、注意事项]。
 *
 * @author sloth-boot
 * @since 1.0.0
 */
```

### 2.3 示例

```java
/**
 * 分布式锁接口。
 * <p>
 * 定义分布式锁的标准操作。默认实现基于 Redisson，
 * 业务方可提供自定义实现覆盖默认 Bean。
 *
 * @author sloth-boot
 * @since 1.0.0
 */
public interface DistributedLock {
```

```java
/**
 * Redis 分布式锁实现。
 * <p>
 * 基于 Redisson 的 {@code RLock}，支持可重入锁、公平锁和读写锁。
 * 使用 {@link TransmittableThreadLocal} 传播锁上下文到异步线程。
 *
 * @author sloth-boot
 * @since 1.0.0
 */
public class RedissonDistributedLock implements DistributedLock {
```

### 2.4 禁止的写法

```java
// 禁止 — 重复类名
/**
 * RedissonDistributedLock
 */
public class RedissonDistributedLock {

// 禁止 — 空注释
/**
 *
 */

// 禁止 — 单行注释用多行格式（接口/简单类除外，可用单行）
/** 分布式锁接口 */
// 此写法允许，但推荐完整 Javadoc 格式
```

## 3. 方法注释规范

### 3.1 必须有 Javadoc 的方法

- 所有 `public` 方法（接口方法、类方法）
- 所有 `protected` 方法
- 所有 `@Override` 方法（如果语义不同于父类则必须注释，否则可省略）
- 所有 `@Bean` 方法

### 3.2 方法注释模板

```java
/**
 * [一句话描述方法功能]。
 *
 * @param paramName  参数说明
 * @return 返回值说明
 * @throws ExceptionType 异常说明（仅在非显而易见时）
 */
```

### 3.3 示例

```java
/**
 * 尝试获取分布式锁。
 *
 * @param lockKey   锁键名
 * @param waitTime  最大等待时间（秒）
 * @param leaseTime 持有时间（秒），-1 表示不自动释放
 * @return 是否获取成功
 */
boolean tryLock(String lockKey, long waitTime, long leaseTime);
```

### 3.4 @Override 方法的注释规则

```java
// 情况 1: 语义与父类一致（如 toString, equals）→ 不加注释
@Override
public String toString() { ... }

// 情况 2: 子类有自己的实现逻辑 → 加注释说明子类行为
/**
 * 释放 Redis 分布式锁。
 * <p>
 * 仅当锁由当前线程持有时才会释放，否则抛出 {@link IllegalMonitorStateException}。
 */
@Override
public void unlock(String lockKey) { ... }
```

### 3.5 @Bean 方法注释

```java
/**
 * 注册分布式锁实现。
 *
 * @param redissonClient Redisson 客户端
 * @return 分布式锁实例
 */
@Bean
@ConditionalOnMissingBean
public DistributedLock distributedLock(RedissonClient redissonClient) {
    return new RedissonDistributedLock(redissonClient);
}
```

## 4. 字段注释规范

### 4.1 必须有注释的字段

- `@ConfigurationProperties` 类的所有字段
- 所有 `public static final` 常量
- 非显而易见的 `private` 字段

### 4.2 注释格式

```java
// @ConfigurationProperties 字段：用 Javadoc（生成 IDE 提示）
/**
 * 锁等待超时时间（秒）
 */
private long waitTime = 30;

// 常量：单行注释或 Javadoc
/** HTTP 请求追踪 ID 头名 */
public static final String HEADER_TRACE_ID = "X-Trace-Id";

// 普通字段：按需
/** 路由定义写入器（用于动态路由增删） */
private final RouteDefinitionWriter routeDefinitionWriter;
```

### 4.3 禁止的写法

```java
// 禁止 — 重复类型信息
/** String 类型的名称 */
private String name;

// 禁止 — 重复字段名
/** name 字段 */
private String name;
```

## 5. package-info.java 规范

### 5.1 强制要求

- **每个存在的 Java 包必须有 `package-info.java`**
- 无 `package-info.java` 的包视为不合规

### 5.2 内容模板

```java
/**
 * [模块名] - [一句话描述该包的职责]。
 * <p>
 * [可选：包含哪些关键类、使用方式]。
 */
package com.sloth.boot.starter.xxx.core;
```

### 5.3 示例

```java
/**
 * Redis 核心能力。
 * <p>
 * 包含 {@link RedisCacheUtil} 缓存工具和 {@link RedisIdGenerator} ID 生成器。
 */
package com.sloth.boot.starter.redis.core;
```

## 7. 禁止的注释模式

| 模式 | 原因 | 示例 |
|------|------|------|
| 分区块标记 | 开发遗留，应通过包/类结构组织 | `// ==================== xxx ====================` |
| 注释掉的代码 | 应删除，通过 git 历史找回 | `// oldMethod();` |
| TODO 不带责任人 | 无人跟进的 TODO 等于没有 | 禁止 `// TODO`，必须 `// TODO(guohuaijian): xxx` |
| 版本注释 | 应通过 git tag 管理 | `// v1.0 添加` |
| 调试注释 | 开发遗留 | `// System.out.println(...)` |

## 8. 中英文规范

| 场景 | 语言 | 示例 |
|------|------|------|
| Javadoc 内容 | 中文 | `/** 分布式锁接口。 */` |
| 代码注释 | 中文 | `// 锁续期失败不影响请求处理` |
| 日志消息（框架级） | 英文 | `log.info("[Redis] Lock acquired")` |
| 日志消息（业务级） | 可中文 | `log.info("[Auth] 用户登录成功")` |
| 变量名/方法名 | 英文 | `tryLock`, `leaseTime` |
| 异常消息 | 英文 | `throw new BizException("Lock timeout")` |

## 9. 检查方法

### 9.1 子代理检查项

```
检查 1: public 类是否有 Javadoc（第一行 /** ）
检查 2: public 方法是否有 Javadoc
检查 3: @ConfigurationProperties 字段是否有 Javadoc
检查 4: 每个包是否有 package-info.java
检查 5: 是否存在分区块标记注释
检查 6: 是否存在注释掉的代码
检查 7: 是否存在无责任人的 TODO
```

### 9.2 Grep 快速检查

```bash
# 检查缺失 package-info 的包
for dir in $(find sloth-boot-common sloth-boot-starter -name "*.java" -not -name "package-info.java" -not -path "*/test/*" | sed 's|/[^/]*\.java||' | sort -u); do
  [ ! -f "$dir/package-info.java" ] && echo "MISSING: $dir/package-info.java"
done
# 通过条件: 无输出

# 检查分区块标记
grep -rn "// ====================" sloth-boot-common/ sloth-boot-starter/ --include="*.java" | grep -v "test"
# 通过条件: 无输出

# 检查无责任人 TODO
grep -rn "// TODO$" --include="*.java" sloth-boot-common/ sloth-boot-starter/ | grep -v test
grep -rn "// TODO:" --include="*.java" sloth-boot-common/ sloth-boot-starter/ | grep -v test
# 通过条件: 无输出（合法格式为 // TODO(name): xxx）
```
