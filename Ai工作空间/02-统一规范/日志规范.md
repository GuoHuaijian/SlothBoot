# 日志规范

> 版本: v1.0 | 制定日期: 2026-05-26 | 阶段: Day 2
> 本文档为 SlothBoot 全项目强制日志规范，所有模块必须遵守。

---

## 1. 日志工具规范

### 1.1 Logger 声明

**强制**：使用 Lombok `@Slf4j` 注解，禁止手动声明 Logger。

```java
// 正确
@Slf4j
public class XxxService { }

// 禁止
private static final Logger log = LoggerFactory.getLogger(XxxService.class);
```

**例外**：`AbstractDecorator` 等需要子类感知的场景可使用 `LoggerFactory.getLogger(getClass())`。

### 1.2 Logger 命名

- Lombok 生成的 Logger 名称为类的全限定名，无需干预
- 禁止使用 `@Log4j`、`@CommonsLog`、`@Log4j2`

## 2. 日志分类与职责

| 类型 | 标签前缀 | 职责 | 日志级别 | 采集方式 | 归属模块 |
|------|----------|------|----------|----------|----------|
| **请求日志** | `[Access]` | HTTP 请求/响应全记录 | INFO | Servlet Filter | common-log |
| **审计日志** | `[Operate]` | 用户操作审计（谁/做了什么/结果） | INFO | `@OperateLog` AOP + Event | common-log |
| **慢操作日志** | `[SlowXxx]` | 慢 SQL、慢 API、慢 ES 查询 | WARN | 拦截器/Filter + Event | 各 starter |
| **错误日志** | `[Error]` | 未捕获异常、系统错误 | ERROR | `GlobalExceptionHandler` | starter-web |
| **业务日志** | `[模块名]` | 业务流程关键节点 | INFO/DEBUG | 手动 | 业务代码 |

## 3. 日志级别使用规范

### 3.1 ERROR — 系统异常，需要人工介入

**使用场景**：
- 未捕获异常导致请求失败
- 数据库连接失败、中间件不可达
- 消息队列消费失败且无法重试
- 分布式事务回滚

**必须**：ERROR 级别日志**必须**包含异常对象（打印堆栈）

```java
// 正确
log.error("[MyBatis] 数据库操作异常 sql={}", sql, e);

// 禁止 — 丢失堆栈
log.error("[MyBatis] 数据库操作异常: " + e.getMessage());
```

### 3.2 WARN — 业务异常，可恢复或需关注

**使用场景**：
- 业务校验失败（参数错误、权限不足）
- 远程调用超时后降级
- 限流/熔断触发
- 可重试的消费失败

```java
// 正确 — 业务异常
log.warn("[Auth] 权限校验失败 userId={}, permission={}", userId, permission);

// 正确 — 限流
log.warn("[Sentinel] 接口限流 resource={}", resourceName);
```

### 3.3 INFO — 关键业务流程节点

**使用场景**：
- 用户登录/登出
- 订单创建/支付/取消
- 请求日志记录
- 审计日志记录
- 系统启动完成

```java
// 正确
log.info("[Auth] 用户登录成功 userId={}, ip={}", userId, ip);
log.info("[Order] 订单创建成功 orderId={}, amount={}", orderId, amount);
```

### 3.4 DEBUG — 开发调试信息

**使用场景**：
- 方法入参出参
- 缓存命中/未命中
- Token 创建/消费（幂等操作的内部流程）
- 配置加载详情

```java
// 正确
log.debug("[Redis] 缓存命中 key={}", cacheKey);
log.debug("[Idempotent] Token 创建成功 key={}", tokenKey);
```

### 3.5 TRACE — 极细粒度

**使用场景**：
- SQL 语句原始参数
- 消息队列原始消息体
- HTTP 原始报文

## 4. 日志消息格式规范

### 4.1 统一消息格式

```
[模块标签] 关键描述 key1={}, key2={}
```

**规则**：
1. **必须**以 `[模块标签]` 开头
2. **必须**使用参数化日志 `{}` 占位符
3. **禁止**字符串拼接（`"key=" + value`）
4. **禁止** `String.format()` 格式化

### 4.2 模块标签规范

标签使用 **PascalCase**，取自模块功能名：

| 模块 | 标签 | 示例 |
|------|------|------|
| 认证授权 | `[Auth]` | `[Auth] 用户登录成功` |
| Redis | `[Redis]` | `[Redis] 分布式锁获取超时` |
| MyBatis | `[MyBatis]` | `[MyBatis] 慢 SQL 执行` |
| Elasticsearch | `[ES]` | `[ES] 慢查询告警` |
| 消息队列 | `[MQ]` | `[MQ] 消息发送失败` |
| 网关 | `[Gateway]` | `[Gateway] 路由转发` |
| AI | `[AI]` | `[AI] 聊天请求完成` |
| 监控 | `[Monitor]` | `[Monitor] 健康检查失败` |
| 线程池 | `[ThreadPool]` | `[ThreadPool] 队列使用率告警` |
| Feign | `[Feign]` | `[Feign] 远程调用超时` |
| 限流 | `[Sentinel]` | `[Sentinel] 触发限流` |
| 审计日志 | `[Operate]` | `[Operate] 操作记录` |
| 请求日志 | `[Access]` | `[Access] HTTP 请求` |
| XSS | `[XSS]` | `[XSS] 检测到恶意输入` |
| 签名 | `[Sign]` | `[Sign] 签名校验失败` |
| 短信 | `[SMS]` | `[SMS] 短信发送成功` |
| OSS | `[OSS]` | `[OSS] 文件上传完成` |
| 幂等 | `[Idempotent]` | `[Idempotent] 重复请求拦截` |

### 4.3 参数化日志规范

```java
// 正确 — 参数化，惰性求值
log.info("[Order] 订单创建 orderId={}, userId={}, amount={}", orderId, userId, amount);

// 禁止 — 字符串拼接，即使日志关闭也会执行
log.info("[Order] 订单创建 orderId=" + orderId + ", userId=" + userId);

// 禁止 — String.format，性能差
log.info(String.format("[Order] 订单创建 orderId=%d", orderId));

// 正确 — DEBUG 级别用条件保护（仅在需要避免昂贵的参数构建时）
if (log.isDebugEnabled()) {
    log.debug("[Redis] 缓存内容 key={}, value={}", key, expensiveSerialize(value));
}
```

## 5. MDC 上下文字段规范

### 5.1 必选字段（所有日志必须携带）

| 字段 | MDC Key | 来源 | 设置时机 |
|------|---------|------|----------|
| 链路追踪 ID | `traceId` | `TraceFilter` 生成 | HTTP 请求入口 |
| 应用名 | `appName` | `spring.application.name` | 应用启动时（logback 配置） |

### 5.2 可选字段

| 字段 | MDC Key | 来源 | 设置时机 |
|------|---------|------|----------|
| 跨度 ID | `spanId` | `TraceContext` | 随 traceId 一起设置 |
| 用户 ID | `userId` | `UserContext` | 认证通过后 |
| 租户 ID | `tenantId` | `UserContext` | 认证通过后 |
| 环境 | `env` | `spring.profiles.active` | 应用启动时（logback 配置） |

### 5.3 上下文传播链路

```
HTTP 请求 → TraceFilter(traceId) → UserContextInterceptor(userId, tenantId)
    ↓
Gateway → TraceIdGlobalFilter(traceId header 透传)
    ↓
Service → TraceContext(TTL) + UserContext(TTL) + MDC
    ↓
Feign → FeignRequestInterceptor(header 透传 traceId, userId, tenantId)
    ↓
MQ → TraceMessageInterceptor(traceId 透传)
    ↓
ThreadPool → TtlTaskDecorator(ContextSnapshot 捕获/恢复)
```

### 5.4 MDC 清理规范

**规则**：在设置 MDC 的 Filter/Interceptor 的 `finally` 块中**必须**调用 `MDC.clear()`。

```java
try {
    MDC.put("traceId", traceId);
    filterChain.doFilter(request, response);
} finally {
    MDC.clear();
}
```

## 6. 敏感数据脱敏规范

### 6.1 脱敏规则表

| 数据类型 | 脱敏规则 | 原始值示例 | 脱敏后示例 |
|----------|----------|-----------|-----------|
| 手机号 | 保留前 3 后 4 | `13812345678` | `138****5678` |
| 身份证 | 保留前 4 后 4 | `110101199001011234` | `1101********1234` |
| 银行卡 | 保留后 4 | `6222021234567890123` | `***********0123` |
| 邮箱 | 保留首字母和域名 | `zhangsan@example.com` | `z***@example.com` |
| 密码 | 完全遮蔽 | `mypassword123` | `******` |
| Token | 完全遮蔽 | `eyJhbGciOi...` | `******` |
| 密钥 | 完全遮蔽 | `sk-abcdef123456` | `******` |
| IP 地址 | 不脱敏（审计需要） | `192.168.1.100` | `192.168.1.100` |

### 6.2 必须脱敏的场景

| 场景 | 脱敏方式 |
|------|----------|
| 请求日志中的 Authorization header | `Bearer ******` |
| 请求日志中的 Cookie header | `Cookie=******` |
| 审计日志中的密码字段 | `******` |
| 任何日志中的 accessKeySecret | `******` |
| 任何日志中的 token 值 | `******` |

### 6.3 禁止记录的内容

- 明文密码
- 数据库连接密码
- 私钥内容
- 完整的信用卡号

## 7. 结构化日志规范

### 7.1 Logback 配置规范

**开发环境（console）**：
```xml
<pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] [%X{traceId:-}] %-5level %logger{36} - %msg%n</pattern>
```

**生产环境（file）**：
```xml
<pattern>{"time":"%d{yyyy-MM-dd'T'HH:mm:ss.SSS}","level":"%level","traceId":"%X{traceId:-}","thread":"%thread","logger":"%logger{36}","msg":"%msg"}%n</pattern>
```

### 7.2 日志文件命名规范

| 文件类型 | 命名格式 | 示例 |
|----------|----------|------|
| 应用日志 | `{appName}.log` | `sloth-example.log` |
| 错误日志 | `{appName}-error.log` | `sloth-example-error.log` |
| 滚动日志 | `{appName}.{日期}.log` | `sloth-example.2026-05-26.log` |

### 7.3 日志文件保留策略

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `maxHistory` | 30 天 | 日志文件保留天数 |
| `maxFileSize` | 100 MB | 单文件最大大小 |
| `totalSizeCap` | 3 GB | 总文件大小上限 |

## 8. 异常日志规范

### 8.1 异常信息记录规范

```java
// 正确 — 业务异常，WARN 级别，包含上下文
log.warn("[Auth] 登录失败 username={}, reason={}", username, e.getMessage());

// 正确 — 系统异常，ERROR 级别，包含堆栈
log.error("[MyBatis] 数据库操作异常 sql={}", sql, e);

// 禁止 — 丢失堆栈
log.error("[MyBatis] 数据库操作异常: " + e.getMessage());

// 禁止 — 手动打印堆栈（应直接传异常对象）
log.error("[MyBatis] 异常: " + ExceptionUtil.getStackTraceAsString(e));

// 禁止 — 记录后继续抛出（会导致重复日志）
log.error("[MyBatis] 异常", e);
throw e;  // 如果上层也会记录，此处不应再记录
```

### 8.2 GlobalExceptionHandler 异常处理规范

| 异常类型 | 日志级别 | 标签 | 说明 |
|----------|----------|------|------|
| `BizException` | WARN | `[Biz]` | 业务异常，可预期 |
| `SystemException` | ERROR | `[System]` | 系统异常，不可预期 |
| `ValidationException` | WARN | `[Validation]` | 参数校验失败 |
| `HttpRequestMethodNotSupportedException` | WARN | `[Web]` | HTTP 方法不支持 |
| 未知异常 | ERROR | `[Unknown]` | 未捕获异常 |

## 9. 框架级日志规范（Starter 模块）

### 9.1 禁止的行为

| 禁止项 | 说明 |
|--------|------|
| `log.info` 记录 Token 创建/消费 | 应为 `log.debug`（高频操作） |
| `log.info` 记录每次缓存命中 | 应为 `log.debug` |
| `log.info` 记录每次锁获取/释放 | 应为 `log.debug` |
| `log.error` 后不传异常对象 | 必须传 `Throwable` 参数 |
| 手动在消息中拼接 `traceId=xxx` | 依赖 MDC，不要手动加 |
| 日志消息使用中文描述 | 框架级日志使用英文（业务日志可用中文） |

### 9.2 推荐的模式

```java
// 方法入口（DEBUG 级别）
log.debug("[Redis] Acquiring distributed lock key={}, timeout={}ms", key, timeoutMs);

// 方法出口（DEBUG 级别）
log.debug("[Redis] Distributed lock acquired key={}, cost={}ms", key, costMs);

// 慢操作告警（WARN 级别）
log.warn("[Redis] Slow distributed lock acquisition key={}, cost={}ms (threshold={}ms)", key, costMs, thresholdMs);

// 异常（ERROR 级别）
log.error("[Redis] Failed to acquire distributed lock key={}", key, e);
```

## 10. 检查方法

### 10.1 Checkstyle 已覆盖

当前 Checkstyle 不检查日志规范。需要新增自定义检查或使用子代理审查。

### 10.2 子代理检查项

```
检查 1: 日志消息是否有 [模块标签] 前缀
检查 2: 是否使用字符串拼接而非参数化日志
检查 3: ERROR 级别是否传递了异常对象
检查 4: 是否有明文密码/token 输出
检查 5: 是否手动在消息中拼接了 traceId
检查 6: Token/缓存等高频操作是否使用了 DEBUG 级别
```

### 10.3 Grep 快速检查

```bash
# 检查 1: 字符串拼接的日志（应使用参数化）
grep -rn 'log\.\(info\|warn\|error\|debug\).*+"' --include="*.java" sloth-boot-starter/ sloth-boot-common/ | grep -v test | head -20
# 通过条件: 无输出或极少

# 检查 2: ERROR 日志不含异常对象
grep -rn 'log\.error(' --include="*.java" sloth-boot-starter/ sloth-boot-common/ | grep -v test | grep -v ', e)' | grep -v ', ex)' | grep -v ', exception)' | head -20
# 需人工确认每条是否合理

# 检查 3: 手动拼接 traceId
grep -rn 'traceId=' --include="*.java" sloth-boot-starter/ sloth-boot-common/ | grep -v test | grep 'log\.' | head -20
# 通过条件: 无输出
```
