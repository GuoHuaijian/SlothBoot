## 1. 测试编写规范

### 1.1 测试分层

| 类型 | 后缀 | 目录 | 用途 | 工具 |
|------|------|------|------|------|
| 单元测试 | `*Test.java` | `src/test/java/` 同包 | 验证单个类/方法逻辑 | JUnit 5 + Mockito |
| 集成测试 | `*IT.java` | `src/test/java/` 同包 | 验证模块交互 | SpringBootTest + Testcontainers |
| AutoConfiguration 测试 | `*AutoConfigurationTest.java` | `src/test/java/` | 验证条件装配正确性 | ApplicationContextRunner |

### 1.2 命名规范

```java
// 测试类: 被测类名 + Test
class RedisAutoConfigurationTest { }

// 测试方法: should_期望行为_when_条件
@Test
void should_register_distributed_lock_bean_when_redisson_on_classpath() { }

// 或: test_场景
@Test
void test_lock_acquisition_timeout() { }
```

### 1.3 AutoConfiguration 测试模板

```java
class XxxAutoConfigurationTest {

    private final ApplicationContextRunner contextRunner = new ApplicationContextRunner()
        .withConfiguration(AutoConfigurations.of(XxxAutoConfiguration.class));

    @Test
    void should_register_beans_when_enabled() {
        contextRunner.run(context -> {
            assertThat(context).hasSingleBean(XxxClient.class);
            assertThat(context).hasSingleBean(XxxProperties.class);
        });
    }

    @Test
    void should_not_register_when_disabled() {
        contextRunner
            .withPropertyValues("sloth.xxx.enabled=false")
            .run(context -> assertThat(context).doesNotHaveBean(XxxClient.class));
    }

    @Test
    void should_allow_user_override() {
        contextRunner
            .withBean(XxxClient.class, () -> mock(XxxClient.class))
            .run(context -> assertThat(context).hasSingleBean(XxxClient.class));
    }
}
```

## 2. Git 提交规范

### 2.1 Commit Message 格式

```
<type>(<scope>): <subject>

<body>

<footer>
```

### 2.2 Type 类型

| Type | 说明 | 示例 |
|------|------|------|
| `feat` | 新功能 | `feat(redis): add bloom filter support` |
| `fix` | Bug 修复 | `fix(auth): fix TokenRenewalFilter condition inversion` |
| `docs` | 文档变更 | `docs: add logging standard document` |
| `style` | 格式调整（不影响逻辑） | `style: remove section marker comments` |
| `refactor` | 重构（不新增功能/不修复 bug） | `refactor(exception): unify RemoteCallException hierarchy` |
| `perf` | 性能优化 | `perf(log): publish operate log events asynchronously` |
| `test` | 测试相关 | `test(core): add unit tests for ObjectUtil` |
| `chore` | 构建/工具变更 | `chore: update JaCoCo coverage threshold` |

### 2.3 Scope 范围

使用模块名（不带 `sloth-boot-` 前缀）：`core`, `log`, `security`, `web`, `redis`, `auth`, `mybatis`, `ai`, `feign`, `gateway`, `mq`, `monitor`, `thread-pool`, `es`, `sentinel`, `excel`, `oss`, `sms`, `job`, `seata`, `idempotent`, `doc`, `test`, `generator`, `deps`

### 2.4 分支命名

```
feat/xxx-feature-name    — 新功能
fix/xxx-bug-description  — Bug 修复
refactor/xxx-target      — 重构
docs/xxx-topic           — 文档
release/x.y.z            — 发布分支
```

## 3. 检查方法

```bash
# 测试类命名检查
find sloth-boot-common sloth-boot-starter -name "*Test.java" -not -path "*/test/*" | head -5
# 通过条件: 无输出（测试类应在 test 目录下）

# AutoConfiguration 测试存在性
find sloth-boot-starter -name "*AutoConfiguration.java" -not -path "*/test/*" | while read f; do
  testfile=$(echo "$f" | sed 's|/main/|/test/|' | sed 's|\.java$|Test.java|')
  [ ! -f "$testfile" ] && echo "MISSING TEST: $testfile"
done
# 记录缺失项（不作为硬性阻断）
```
