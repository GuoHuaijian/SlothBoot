# 代码结构与包命名规范

> 版本: v1.0 | 制定日期: 2026-05-25 | 阶段: Day 1
> 本文档为 SlothBoot 全项目强制规范，所有模块必须遵守。

---

## 1. 模块命名规范

### 1.1 Maven 模块命名

| 层级 | 格式 | 示例 |
|------|------|------|
| BOM | `sloth-boot-dependencies` | — |
| 父 POM | `sloth-boot-parent` | — |
| common 层 | `sloth-boot-common-{功能}` | `sloth-boot-common-core`, `sloth-boot-common-log` |
| starter 层 | `sloth-boot-starter-{能力}` | `sloth-boot-starter-redis`, `sloth-boot-starter-ai` |
| 生成器 | `sloth-boot-generator` | — |
| 示例 | `sloth-boot-example` | — |

**规则**：
- 单词间用 `-` 连接，全小写
- common 层模块必须以 `sloth-boot-common-` 为前缀
- starter 层模块必须以 `sloth-boot-starter-` 为前缀
- 功能/能力名称使用英文名词，简洁且无歧义

**检查方法**：
```bash
# 验证模块命名格式
find . -maxdepth 3 -name "pom.xml" -not -path "./.git/*" | xargs grep "<artifactId>" | grep -v "sloth-boot" | grep -v "spring" | grep -v "mybatis" | head -20
```

### 1.2 包名与模块名的映射

| Maven artifactId | 根包名 |
|-------------------|--------|
| `sloth-boot-common-core` | `com.sloth.boot.common` |
| `sloth-boot-common-log` | `com.sloth.boot.common.log` |
| `sloth-boot-common-security` | `com.sloth.boot.common.security` |
| `sloth-boot-common-test` | `com.sloth.boot.common.test` |
| `sloth-boot-common-doc` | `com.sloth.boot.common.doc` |
| `sloth-boot-starter-{name}` | `com.sloth.boot.starter.{name}` |
| `sloth-boot-generator` | `com.sloth.boot.generator` |

**规则**：
- 包名 = `com.sloth.boot.` + 层级 + `.{功能名}`
- starter 的包名中功能名与模块名一致，但 `-` 改为省略（如 `starter-redis` → `starter.redis`）
- **例外**：`sloth-boot-starter-thread-pool` → `com.sloth.boot.starter.thread`（避免 `thread-pool` 的连字符）

**检查方法**：
```bash
# 验证包名一致性
for f in $(find sloth-boot-starter -name "package-info.java" -not -path "*/test/*"); do
  pkg=$(grep "^package" "$f" | sed 's/package //; s/;//')
  echo "$f -> $pkg"
done
```

## 2. 包结构规范

### 2.1 common-core 标准包结构

```
com.sloth.boot.common
  ├── annotation/        # 通用注解（仅框架级注解，禁止业务注解）
  ├── base/              # 基础模型（BaseEntity, BaseDTO, BaseVO, BaseQuery, TreeNode）
  ├── config/            # 自动配置类
  ├── constant/          # 通用常量（仅框架级常量）
  ├── context/           # 线程上下文（TraceContext, UserContext）
  ├── enums/             # 通用枚举（实现 IBaseEnum 接口）
  ├── event/             # 事件基础设施（BaseEvent, EventPublisher, AbstractEventListener）
  ├── exception/         # 异常体系（BaseException, BizException, SystemException, ErrorCode）
  ├── result/            # 统一响应（R, PageResult）
  ├── util/              # 工具类（纯静态工具，无状态）
  │   └── jackson/       # Jackson 序列化器/反序列化器
  ├── decorator/         # 装饰器基类
  ├── interceptor/       # 拦截器基类
  └── lifecycle/         # 生命周期管理
```

**禁止放入 common-core 的内容**：
- 业务注解（如 `@DistributedLock`, `@RateLimit`, `@DataScope`）→ 放到对应 starter
- 业务枚举（如 `GenderEnum`）→ 放到业务模块
- 业务常量（如 `USER_CACHE_PREFIX`, `ROLE_CACHE_PREFIX`）→ 放到业务模块或对应 starter
- 第三方 SDK 的强依赖实现

### 2.2 common 其他模块标准包结构

```
com.sloth.boot.common.{module}
  ├── config/            # 自动配置类（AutoConfiguration）
  ├── properties/        # 配置属性类（@ConfigurationProperties）
  ├── filter/            # Servlet/WebFlux Filter
  ├── aspect/            # AOP 切面
  ├── event/             # 事件定义与监听器
  ├── model/             # DTO/模型类
  └── package-info.java  # 包级文档
```

### 2.3 starter 层标准包结构

```
com.sloth.boot.starter.{module}
  ├── config/            # 自动配置类 + 配置属性类
  ├── core/              # 核心实现（Client, Template, Manager 等）
  ├── annotation/        # 模块专属注解（按需）
  ├── aspect/            # AOP 切面（按需）
  ├── filter/            # Servlet/WebFlux Filter（按需）
  ├── handler/           # 处理器（按需）
  ├── interceptor/       # 拦截器（按需）
  ├── listener/          # 事件监听器（按需）
  ├── event/             # 事件定义（按需）
  ├── model/             # DTO/模型类（按需）
  ├── spi/               # SPI 扩展点接口 + 默认实现（按需）
  ├── health/            # HealthIndicator（按需）
  ├── metrics/           # Micrometer 指标（按需）
  ├── endpoint/          # Actuator Endpoint（按需）
  ├── support/           # 支撑类（辅助工具，非核心）
  └── package-info.java  # 每个存在的包必须有
```

**规则**：
- **禁止**自定义子包名（如 `bloom/`, `delay/`, `id/`）。starter-redis 中已有的这类子包在重构时合并到 `core/` 或 `support/`
- `config/` 包同时存放 `*AutoConfiguration.java` 和 `*Properties.java`（统一标准，消除当前 `config/` vs `properties/` 的不一致）
- 每个包内至少有 1 个实质类时才创建该包，禁止空包

**当前不一致项（需在阶段四修正）**：

| Starter | Properties 当前位置 | 目标位置 |
|---------|---------------------|----------|
| starter-auth | `properties/` | `config/` |
| starter-excel | `properties/` | `config/` |
| starter-web | `properties/` | `config/` |

**检查方法**：
```bash
# 检查 Properties 是否在 config 包中
find sloth-boot-starter -name "*Properties.java" -not -path "*/config/*" -not -path "*/test/*"
# 通过条件: 无输出
```

### 2.4 包深度规则

**规则**：
- common 层：最多 2 级子包（`com.sloth.boot.common.{pkg}.{subpkg}`）
- starter 层：最多 2 级子包（`com.sloth.boot.starter.{module}.{subpkg}`）
- 禁止超过 3 级包嵌套

**检查方法**：
```bash
# 检查是否有超过 3 级的子包
find sloth-boot-common sloth-boot-starter -name "*.java" -not -path "*/test/*" | \
  sed 's|.*/java/||; s|/[^/]*\.java||' | awk -F'/' '{if(NF>4) print $0}' | sort -u
# 通过条件: 无输出
```

## 3. 类命名规范

### 3.1 通用规则

| 规则 | 格式 | Checkstyle 规则 |
|------|------|-----------------|
| 类名/接口名 | UpperCamelCase | `TypeName` (`^[A-Z][a-zA-Z0-9]*$`) |
| 方法名 | lowerCamelCase | `MethodName` (`^[a-z][a-z0-9][a-zA-Z0-9]*$`) |
| 参数名 | lowerCamelCase | `ParameterName` |
| 局部变量 | lowerCamelCase | `LocalVariableName` |
| 成员变量 | lowerCamelCase | `MemberName` |
| 包名 | 全小写，单词间不用 `-` | `PackageName` |

### 3.2 类名后缀约定

| 后缀 | 用途 | 使用场景 | 示例 |
|------|------|----------|------|
| `Util` | 静态工具类（纯函数，无状态） | common-core/util | `JsonUtil`, `DateUtil`, `CollectionUtil` |
| `Helper` | 有状态的辅助类（可注入） | 按需 | 当前未使用，不推荐新增 |
| `Template` | 模板类（封装操作流程） | starter 层 | `OssTemplate`, `SmsTemplate`, `EsTemplate` |
| `Client` | 客户端接口/实现 | starter 层 | `OssClient`, `SmsClient`, `AiChatClient` |
| `Service` | 服务类 | starter + 业务层 | `TokenIdempotentService`, `OnlineUserService` |
| `Handler` | 处理器（处理特定类型） | starter 层 | `AbstractJobHandler`, `GlobalExceptionHandler` |
| `Filter` | Servlet/Reactive Filter | common + starter | `TraceFilter`, `RequestLogFilter` |
| `Interceptor` | 拦截器 | starter 层 | `SlowSqlInterceptor`, `FeignRequestInterceptor` |
| `Aspect` | AOP 切面 | starter 层 | `IdempotentAspect`, `DistributedLockAspect` |
| `Listener` | 事件监听器 | common + starter | `OperateLogListener`, `SaTokenEventListener` |
| `Event` | 事件类 | common + starter | `LoginEvent`, `AccessLogEvent` |
| `Indicator` | 健康检查 | starter 层 | `NacosHealthIndicator`, `EsHealthIndicator` |
| `Registry` | 注册中心 | starter 层 | `ThreadPoolRegistry`, `AiFunctionRegistry` |
| `Manager` | 管理器（生命周期管理） | starter 层 | `ThreadPoolManager` |
| `Endpoint` | Actuator 端点 | starter 层 | `InfoEndpoint`, `ThreadPoolEndpoint` |
| `Factory` | 工厂类 | starter 层 | `AbstractFallbackFactory` |
| `Decorator` | 装饰器 | common-core | `AbstractDecorator`, `LoggingDecorator` |
| `Wrapper` | 包装器 | common-security | `XssHttpServletRequestWrapper` |
| `Validator` | 校验器 | starter-web | `EnumValueValidator`, `PhoneValidator` |

**禁止的命名**：
- 禁止使用 `Utils`（应为 `Util`，单数）
- 禁止使用 `XxxHelper` + `XxxUtil` 并存于同一模块
- 禁止使用 `Manager` + `Service` 表达同一职责

### 3.3 泛型参数命名

| 参数 | 用途 | 示例 |
|------|------|------|
| `T` | 通用类型 | `R<T>`, `BaseEntity` |
| `E` | 枚举元素类型 | `IBaseEnum<E>` |
| `K` | Map 键类型 | — |
| `V` | Map 值类型 | — |
| `R` | 返回值类型 | — |
| `ID` | 主键类型 | `BaseEntity<ID>` |

## 4. 常量命名规范

**规则**：
- 常量名：`UPPER_SNAKE_CASE` — Checkstyle: `ConstantName`
- `static final` 字段才用大写，非 final 的 static 字段用 lowerCamelCase
- 常量值为魔法数字时必须定义为常量（Checkstyle: `MagicNumber`）

**前缀规范**：

| 常量类型 | 前缀 | 示例 |
|----------|------|------|
| HTTP 头名 | 无 | `HEADER_TRACE_ID = "X-Trace-Id"` |
| 缓存 Key 前缀 | 无 | `CACHE_KEY_USER = "user:"` |
| 错误码 | 无 | `SUCCESS = 0`, `INTERNAL_ERROR = 500` |
| 默认值 | `DEFAULT_` | `DEFAULT_PAGE_SIZE = 10` |

**禁止**：
- 禁止定义 `NUM_ZERO = 0`, `NUM_ONE = 1` 这类无意义常量（当前 `CommonConstant` 中存在，需清理）
- 禁止在接口中定义常量（应使用 `final class` 或 `enum`）

## 5. AutoConfiguration 类规范

### 5.1 命名规则

- 命名格式：`{Module}AutoConfiguration`
- 位置：`config` 子包
- 示例：`RedisAutoConfiguration`, `AiAutoConfiguration`, `WebAutoConfiguration`

### 5.2 注解规范

```java
@AutoConfiguration(after = SomeDependency.class)   // 必须：指定加载顺序（如有依赖）
@ConditionalOnClass(RequiredClass.class)            // 必须：检查核心依赖类存在
@ConditionalOnProperty(                             // 必须：模块级开关
    prefix = "sloth.{module}",
    name = "enabled",
    havingValue = "true",
    matchIfMissing = true
)
@EnableConfigurationProperties(XxxProperties.class) // 必须：绑定配置属性
public class XxxAutoConfiguration {
```

**规则**：
- 每个 `@Bean` 方法必须标注 `@ConditionalOnMissingBean`（允许用户替换）
- 禁止使用 `@Configuration`（使用 `@AutoConfiguration`）
- 禁止使用 `@Bean` + `@ConditionalOnClass` 做 provider 选择时缺少 class 存在性检查
- 多个 AutoConfiguration 之间用 `after` / `before` 排序

### 5.3 注册方式

文件路径：`src/main/resources/META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`

内容格式（每行一个全限定类名）：
```
com.sloth.boot.starter.xxx.config.XxxAutoConfiguration
```

**禁止**：使用已废弃的 `spring.factories` 注册 AutoConfiguration

## 6. 配置属性类规范

### 6.1 命名规则

- 命名格式：`{Module}Properties`
- 位置：`config` 子包（统一标准，消除当前 `config/` vs `properties/` 的不一致）
- 前缀：`sloth.{module}`

### 6.2 注解规范

```java
@Data
@ConfigurationProperties(prefix = "sloth.{module}")
public class XxxProperties {

    /**
     * 是否启用
     */
    private boolean enabled = true;

    // 其他属性...
}
```

**规则**：
- 使用 Lombok `@Data`（或 `@Getter` + `@Setter`）
- 每个字段必须有 Javadoc 注释（生成 IDE 提示）
- `enabled` 字段默认 `true`（Seata 除外，其默认 `false`）
- 嵌套配置使用静态内部类

### 6.3 元数据文件

每个 starter 必须有自己的：
`src/main/resources/META-INF/spring-configuration-metadata-additional.json`

**禁止**：在 common-core 中集中管理所有 starter 的配置元数据

## 7. 测试类命名规范

| 类型 | 命名格式 | 位置 |
|------|----------|------|
| 单元测试 | `{ClassName}Test.java` | `src/test/java/` 同包路径 |
| 集成测试 | `{ClassName}IT.java` | `src/test/java/` 同包路径 |
| 测试基类 | `Base{Type}Test.java` | `com.sloth.boot.common.test` |

**规则**：
- 测试类名 = 被测类名 + `Test` 后缀
- 测试方法名：`should_{期望行为}_when_{条件}` 或 `test_{场景}`
- 测试类与被测类在同一包路径下

## 8. 资源文件规范

### 8.1 标准目录结构

```
src/main/resources/
  ├── META-INF/
  │   ├── spring/
  │   │   └── org.springframework.boot.autoconfigure.AutoConfiguration.imports
  │   └── spring-configuration-metadata-additional.json
  └── scripts/               # Lua/SQL 脚本（按需）
```

### 8.2 资源文件命名

- Lua 脚本：`{功能}.lua`（如 `release_lock.lua`, `rate_limiter.lua`）
- SQL 脚本：`{版本}_{描述}.sql`（如 `init.sql`）
- 配置文件：`application*.yml`（禁止 `.properties` 格式）
