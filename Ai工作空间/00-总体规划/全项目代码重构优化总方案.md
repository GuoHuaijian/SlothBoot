## 二、必须修复的安全问题（P0）

### S-01: XSS 正则可绕过

**位置**: `common-security/XssCleaner.java`
**问题**: `EVENT_PATTERN` 仅匹配带引号的事件处理器，无引号值 `<img onerror=alert(1)>` 可绕过
**修复**: 引入 `org.jsoup` 或 OWASP HTML Sanitizer 替代正则
**影响**: 所有使用 XSS 防护的 Web 应用

### S-02: 签名校验未验证时间戳

**位置**: `common-security/SignUtil.java`
**问题**: `verifySign()` 只比较签名，不检查 timestamp 是否在 `validTime`(300s) 窗口内，可无限重放
**修复**: 增加 `System.currentTimeMillis() - timestamp > validTime * 1000L` 校验
**影响**: 所有使用请求签名的 API

### S-03: SecurityUtil.hashPassword 使用不安全的 SHA-256

**位置**: `common-core/SecurityUtil.java`
**问题**: `hashPassword()` 使用 `sha256(salt + password)` 单轮哈希，远不如 BCrypt 安全
**修复**: 删除 `hashPassword/verifyPassword/generateSalt`，引导用户使用 `HashUtil.bcrypt()`
**影响**: 使用 SecurityUtil 做密码哈希的应用

### S-04: DataScope SQL 拼接注入风险

**位置**: `starter-mybatis/DataScopeInterceptor.java`
**问题**: JSqlParser 失败后 fallback 路径直接拼接 `@DataScope` 的 `userAlias/deptAlias` 到 SQL
**修复**: 对 alias 值做正则白名单校验（只允许 `[a-zA-Z0-9_.]`）
**影响**: 使用 @DataScope 的所有查询

## 三、必须修复的 Bug（P0）

### B-01: TokenRenewalFilter 注册条件反转

**位置**: `starter-auth/AuthAutoConfiguration.java:136`
**问题**: `havingValue="-1"` 表示"禁用时注册"，但 Filter 内部检查 `>0` 才执行，逻辑矛盾
**修复**: 改为 `havingValue` 不等于 `-1` 时注册

### B-02: LoginEvent 丢失 IP 和 UserAgent

**位置**: `starter-auth/SaTokenEventListener.java:195`
**问题**: `new LoginEvent(this, userId, loginType, null, null, device)` — IP 和 UA 始终为 null
**修复**: 从 `SaHolder.getRequest()` 获取实际 IP 和 UA

### B-03: SpringContextUtil.getActiveProfile() 越界

**位置**: `common-core/SpringContextUtil.java:82`
**问题**: `getActiveProfiles()[0]` 在无 profile 时抛 `ArrayIndexOutOfBoundsException`
**修复**: 加空数组检查，返回 `"default"` 兜底

### B-04: 延迟队列消息静默丢失

**位置**: `starter-redis/RedisDelayQueue.java:54-64`
**问题**: `LinkedBlockingQueue(1)` + `DiscardPolicy` — 队列满时消息被静默丢弃
**修复**: 改为有界队列 + `CallerRunsPolicy`，或使用 `SynchronousQueue`

### B-05: DLQ Handler 内存泄漏 + 线程泄漏

**位置**: `starter-mq/DeadLetterQueueHandler.java`
**问题**: `retryCounters` ConcurrentHashMap 无上限增长；`destroy()` 未实现 `DisposableBean`，ScheduledExecutorService 泄漏
**修复**: 实现 `DisposableBean`；retryCounters 加 TTL 或定期清理

### B-06: Gateway 路由只增不删

**位置**: `starter-gateway/DynamicRouteService.java:85-99`
**问题**: `refreshRoutes()` 只 `save()` 不 `delete()`，从 Nacos 移除的路由永远残留
**修复**: 记录已加载路由 ID，刷新时对比并删除不再存在的

### B-07: Gateway ConfigService 资源泄漏

**位置**: `starter-gateway/DynamicRouteService.java:63`
**问题**: `NacosFactory.createConfigService()` 创建后不存储、不关闭
**修复**: 保存引用，实现 `DisposableBean` 在销毁时调用 `shutDown()`

## 四、架构级重构（P1）

### A-01: JsonUtil 与 JacksonConfigUtil 双 ObjectMapper 统一

**位置**: `common-core/util/JsonUtil.java` + `common-core/util/jackson/JacksonConfigUtil.java`
**问题**: 两套 ObjectMapper 配置产生不同序列化行为 — JsonUtil 用 `SimpleDateFormat`+`GMT+8`，JacksonConfigUtil 用 `JavaTimeModule`
**修复**: `JsonUtil` 的静态 ObjectMapper 改为使用 `JacksonConfigUtil.createConfiguredMapper()`
**效果**: 所有序列化路径统一行为

### A-02: SecurityUtil 与 HashUtil 重复消除

**位置**: `common-core/SecurityUtil.java` + `common-security/HashUtil.java`
**问题**: `md5()`, `sha256()` 在两个类中各实现一遍，密码哈希还有安全 vs 不安全两个版本
**修复**:
- SecurityUtil 删除 `md5/sha256/hashPassword/verifyPassword/generateSalt/mask`
- 保留 `hmacSha256`, `generateRandomString`
- 用户统一使用 `HashUtil`（common-security）

### A-03: 业务注解迁出 common-core

**位置**: `common-core/annotation/` 目录
**问题**: `@DistributedLock`, `@RateLimit`, `@LimitType`, `@NoRepeatSubmit`, `@DataScope`, `@InnerAuth` 定义在 common-core，但实现在各自 starter
**迁移计划**:
- `@DistributedLock` + `@RateLimit` + `@LimitType` → `starter-redis`
- `@Idempotent` + `@IdempotentType` → `starter-idempotent`
- `@DataScope` + `DataScopeEnum` → `starter-mybatis`
- `@InnerAuth` → `starter-auth`
- `@NoRepeatSubmit` → `starter-redis`（或删除，被 @Idempotent 覆盖）
- `@OperateLog` + `OperateTypeEnum` → `common-log`（职责对口）
- `@Desensitize` + `@DesensitizeType` → `common-security`（职责对口）

**注意**: 这是破坏性变更，需同步更新所有引用方的 import

### A-04: 配置元数据从 common-core 分拆到各 starter

**位置**: `common-core/META-INF/additional-spring-configuration-metadata.json`（992 行）
**修复**: 每个 starter 维护自己的元数据 JSON，common-core 只保留 `sloth.i18n.*`

### A-05: starter-web 匿名 Filter 提取为命名类

**位置**: `starter-web/WebAutoConfiguration.java:122-223`
**问题**: XSS Filter、Body Cache Filter、Access Log Filter 都是匿名内部类，无法单独测试
**修复**:
- 提取为 `XssFilter`（已有，在 common-security 中）、`BodyCacheFilter`、`AccessLogFilter`
- 每个 Filter 独立命名类，可注入、可替换、可测试

### A-06: starter-redis 内嵌 IdempotentAspect 清除

**位置**: `starter-redis/idempotent/` 整个子包
**问题**: 与 `starter-idempotent` 功能重复，仅 67 行的简化版，用字符串 type 排除很脆弱
**修复**: 删除整个 `idempotent` 子包 + AutoConfiguration 中的相关 Bean 注册

### A-07: starter-redis SpelExpressionSupport 死代码删除

**位置**: `starter-redis/support/SpelExpressionSupport.java`
**问题**: 已标记 `@Deprecated(forRemoval = true)`，所有调用方已迁移
**修复**: 直接删除

### A-08: Monitor BeanPostProcessor hack 移除

**位置**: `starter-monitor/MonitorAutoConfiguration.java:196-213`
**问题**: 强制修改 `WebEndpointProperties` 暴露端点，与用户配置冲突
**修复**: 删除 BeanPostProcessor，改为文档引导 + 可选的 `@ConditionalOnProperty` 开关

### A-09: MQ 反射双路径事务消息清理

**位置**: `starter-mq/MessageProducer.java:135-166`
**问题**: 先尝试 4 参数方法，NoSuchMethodException 后尝试 3 参数，脆弱
**修复**: 确定 RocketMQ Spring 版本，使用正确 API 一次调用

### A-10: Starter 分区标记注释清理

**位置**: 多个 AutoConfiguration 中的 `// ==================== 新增特性 ====================`
**文件**: `RedisAutoConfiguration:162`, `AuthAutoConfiguration:99`, `ThreadPoolAutoConfiguration:213`, `MonitorAutoConfiguration:172`, `MQAutoConfiguration:54`
**修复**: 删除所有此类分区标记注释

## 五、设计优化（P1）

### D-01: LogProperties 开关拆分

**位置**: `common-log/LogProperties.java`
**问题**: `printRequestLog` 同时控制 HTTP 请求日志和审计日志
**修复**: 拆为 `printAccessLog` + `printOperateLog`

### D-02: OperateLogAspect 异步事件发布

**位置**: `common-log/OperateLogAspect.java`
**问题**: 使用原始 `ApplicationEventPublisher` 同步发布，阻塞请求线程
**修复**: 注入 `EventPublisher`，使用 `publishAsync()`

### D-03: RequestLogFilter 敏感头脱敏增强

**位置**: `common-log/RequestLogFilter.java:95-108`
**问题**: 仅遮蔽 `Authorization`，`Cookie`、`X-Real-IP` 等明文输出
**修复**: 维护敏感头名列表：`Authorization`, `Cookie`, `Set-Cookie`, `X-Forwarded-For`

### D-04: @EnableAsync 条件化

**位置**: `starter-thread-pool/ThreadPoolAutoConfiguration.java:36`
**问题**: 无条件激活 `@EnableAsync`，用户只想要线程管理也会被迫开启异步
**修复**: 增加 `@ConditionalOnProperty(prefix="sloth.thread-pool", name="async-enabled", matchIfMissing=true)`

### D-05: GlobalExceptionHandler 可选依赖处理优化

**位置**: `starter-web/GlobalExceptionHandler.java:213-243`
**问题**: `Class.forName()` 字符串方式检查可选异常类，异常被静默吞没
**修复**: 提取为 `ExceptionTypeResolver` 工具类，初始化时一次性扫描并缓存

### D-06: RocketMQHealthIndicator 反射改强类型

**位置**: `starter-monitor/RocketMQHealthIndicator.java`
**问题**: 接收 `Object rocketMQTemplate` 然后反射调方法，脆弱
**修复**: 改为 `@ConditionalOnClass(RocketMQTemplate.class)` + 强类型参数

### D-07: NacosHealthIndicator 真正检查连通性

**位置**: `starter-monitor/NacosHealthIndicator.java:32-41`
**问题**: 仅读配置属性报告地址，不实际检查连接
**修复**: 通过 Nacos Open API 调用 `/nacos/v1/ns/raft/leader` 或 `/nacos/v1/console/health/readiness`

### D-08: AuthGlobalFilter 重命名为 HeaderPassthroughFilter

**位置**: `starter-gateway/filter/AuthGlobalFilter.java`
**问题**: 名为 "Auth" 但只检查 header 存在性，不验证 token，误导性强
**修复**: 重命名为 `HeaderForwardingFilter`，或增加真正的 token 验证逻辑

### D-09: OssTemplate 无价值委托层重构

**位置**: `starter-oss/OssTemplate.java`
**问题**: 纯委托，零逻辑添加，多一层无意义包装
**修复**: 改为 abstract 装饰器基类（加日志/指标/重试能力），或删除直接使用 OssClient

### D-10: MinioOssClient.listFiles 静默返回空

**位置**: `starter-oss/MinioOssClient.java:101`
**问题**: 返回 `Collections.emptyList()` 而非抛异常或实现
**修复**: 使用 MinIO `listObjects()` API 实现，或抛 `UnsupportedOperationException`

### D-11: EncryptTypeHandler 弱密钥派生

**位置**: `starter-mybatis/EncryptTypeHandler.java:109`
**问题**: `StrUtil.fillAfter(key, '0', 16).substring(0, 16)` — 零填充截断不是安全的密钥派生
**修复**: 使用 `MessageDigest.getInstance("SHA-256")` 派生密钥并截取

### D-12: BaseMapperX.insertBatch 假批量

**位置**: `starter-mybatis/BaseMapperX.java:55-64`
**问题**: for 循环逐条 INSERT，误导性命名
**修复**: 重命名为 `insertOneByOne`，并标注推荐使用 `InsertBatchSomeColumn`

### D-13: DeviceStrategy.PROHIBIT 未实现

**位置**: `starter-auth/SaTokenEventListener.java:53-56`
**问题**: 枚举值存在但无处理逻辑，误导用户
**修复**: 实现拒绝新登录的逻辑，或标记 `@Deprecated` 并文档说明

### D-14: Excel AutoConfiguration 空壳化

**位置**: `starter-excel/ExcelAutoConfiguration.java`
**问题**: 零 Bean 注册，不算真正的 starter
**修复**: 注册 `ExcelTemplate` bean（封装 ExcelUtil 的 Bean 版本），支持注入和自定义
