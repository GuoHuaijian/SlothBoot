### 1.2 模块依赖方向（强制）

```
                ┌─────────┐
                │ example  │ ← 只有 example 可以依赖 starter
                └────┬────┘
                     │
        ┌────────────┼────────────┐
        ▼            ▼            ▼
   ┌─────────┐ ┌─────────┐ ┌─────────┐
   │ starterA │ │ starterB │ │ starterC │  ← starter 之间禁止直接依赖
   └────┬────┘ └────┬────┘ └────┬────┘
        │            │            │
        ▼            ▼            ▼
   ┌───────────────────────────────────┐
   │     common-core (基础层)           │  ← 所有 starter 依赖 common-core
   │     common-log / security / ...   │  ← common 模块之间互不依赖
   └───────────────┬───────────────────┘
                   │
                   ▼
   ┌───────────────────────────────────┐
   │     sloth-boot-parent (父 POM)     │
   │     sloth-boot-dependencies (BOM)  │
   └───────────────────────────────────┘
```

**依赖规则**：

| 规则 | 说明 |
|------|------|
| R-01 | common 层模块之间**禁止**相互依赖 |
| R-02 | starter 之间**禁止**直接依赖 |
| R-03 | starter → common-core **允许** |
| R-04 | starter → 其他 common 模块**允许**（如 web → log） |
| R-05 | 禁止反向依赖（common → starter） |
| R-06 | 禁止循环依赖 |
| R-07 | 唯一例外：`starter-idempotent → starter-redis`（记录决策原因） |

## 二、Starter 架构规范

### 2.1 自动装配模型

```
用户引入 starter 依赖
         │
         ▼
Spring Boot 扫描 META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports
         │
         ▼
@AutoConfiguration 类被加载
         │
         ├── @ConditionalOnClass 检查 → 类不存在则跳过
         ├── @ConditionalOnProperty 检查 → enabled=false 则跳过
         │
         ▼
@EnableConfigurationProperties 绑定 *Properties
         │
         ▼
@Bean 方法执行，每个 Bean 检查 @ConditionalOnMissingBean
         │
         ▼
Bean 注册完成，用户可通过自己的 @Bean 覆盖任何默认实现
```

### 2.2 每个 Starter 必须提供的能力

| 能力 | 必须/建议 | 说明 |
|------|-----------|------|
| `@AutoConfiguration` | **必须** | 禁止使用 `@Configuration` |
| `@ConditionalOnClass` | **必须** | 检查核心依赖库是否在 classpath |
| `@ConditionalOnProperty` | **必须** | `sloth.{module}.enabled` 开关 |
| `@EnableConfigurationProperties` | **必须** | 绑定配置属性 |
| `@ConditionalOnMissingBean` | **必须** | 每个公开 Bean 允许用户替换 |
| `*Properties` 配置类 | **必须** | 在 `config/` 包中 |
| `package-info.java` | **必须** | 每个包都有 |
| `spring-configuration-metadata-additional.json` | **必须** | 每个 starter 自维护 |
| `HealthIndicator` | **建议** | 涉及外部依赖时提供 |
| `Micrometer Metrics` | **建议** | 关键操作指标 |
| `Spring Event` | **建议** | 关键生命周期事件 |
| `SPI 扩展点` | **建议** | 允许用户替换存储/策略/行为 |

### 2.3 Starter 包结构标准

```
com.sloth.boot.starter.{module}/
  ├── config/           # AutoConfiguration + Properties
  ├── core/             # 核心实现
  ├── annotation/       # 模块专属注解（按需）
  ├── aspect/           # AOP 切面（按需）
  ├── filter/           # Servlet/Reactive Filter（按需）
  ├── handler/          # 处理器（按需）
  ├── interceptor/      # 拦截器（按需）
  ├── listener/         # 事件监听器（按需）
  ├── event/            # 事件定义（按需）
  ├── model/            # DTO/模型类（按需）
  ├── spi/              # SPI 扩展点（按需）
  ├── health/           # HealthIndicator（按需）
  ├── metrics/          # Micrometer 指标（按需）
  ├── endpoint/         # Actuator Endpoint（按需）
  └── support/          # 支撑类（按需）
```

## 三、事件驱动架构

### 3.1 事件模型

```
                    ┌──────────────────────┐
                    │  BaseEvent (common)   │
                    │  + traceId            │
                    │  + eventTime          │
                    │  + source             │
                    └──────────┬───────────┘
                               │
          ┌────────────────────┼────────────────────┐
          │                    │                     │
   ┌──────▼──────┐    ┌───────▼──────┐    ┌────────▼────────┐
   │ LoginEvent  │    │AccessLogEvent│    │SlowOperationEvent│
   │ (auth)      │    │ (web)        │    │ (各starter发布)  │
   └─────────────┘    └──────────────┘    └─────────────────┘
```

### 3.2 事件发布规范

| 规则 | 说明 |
|------|------|
| E-01 | 事件类继承 `BaseEvent`（common-core） |
| E-02 | 事件发布通过 `EventPublisher`（common-core），支持同步/异步 |
| E-03 | 异步事件使用虚拟线程（`publishAsync()`） |
| E-04 | 事件监听使用 `@EventListener` 或继承 `AbstractEventListener` |
| E-05 | 模块间通过事件解耦，禁止直接调用其他 starter 的内部类 |

### 3.3 事件清单（目标状态）

| 事件 | 发布方 | 监听方 | 用途 |
|------|--------|--------|------|
| `LoginEvent` | starter-auth | 业务层 | 登录审计 |
| `AccessLogEvent` | common-log | 业务层 | 请求日志持久化 |
| `OperateLogEvent` | common-log | 业务层 | 审计日志持久化 |
| `SlowOperationEvent` | 各 starter | starter-monitor | 慢操作告警 |
| `IdempotentRejectedEvent` | starter-idempotent | 业务层 | 重复请求审计 |
| `GlobalTransactionEvent` | starter-seata | 业务层 | 事务生命周期审计 |
| `JobExecutionEvent` | starter-job | 业务层 | 任务执行审计 |
| `SmsSentEvent` / `SmsFailedEvent` | starter-sms | 业务层 | 短信发送审计 |
| `MessageFailureLogEvent` | starter-mq | 业务层 | 消息失败审计 |
| `ThreadPoolAlarmEvent` | starter-thread-pool | starter-monitor | 线程池告警 |

## 四、可观测架构

### 4.1 三层可观测性

```
┌─────────────────────────────────────────────┐
│               可观测平台                      │
│         Grafana / Kibana / Prometheus        │
├──────────┬──────────────┬───────────────────┤
│ Traces   │   Metrics    │     Logs          │
│ 链路追踪  │   指标监控    │     日志           │
├──────────┼──────────────┼───────────────────┤
│ traceId  │ Micrometer   │ 结构化 JSON 日志   │
│ spanId   │ Counter      │ MDC 上下文         │
│ MDC      │ Timer        │ 分类日志           │
│ OTel     │ Gauge        │ 日志级别规范        │
└──────────┴──────────────┴───────────────────┘
```

### 4.2 上下文传播全链路

```
客户端 → Gateway(Filter) → Service(Filter+Interceptor) → DB(Interceptor)
                                    ↓
                              Feign(Interceptor) → 下游 Service
                                    ↓
                              MQ(Interceptor) → Consumer
                                    ↓
                              ThreadPool(TtlDecorator) → 异步任务
                                    ↓
                              Job(AbstractJobHandler) → 定时任务
```

每个环节都**必须**传播：`traceId`, `userId`, `tenantId`

## 五、安全架构

### 5.1 认证授权流程

```
请求进入 → 白名单检查 → 黑名单检查 → Token 提取 → Sa-Token 校验 → UserContext 设置 → 业务处理
                                ↓ (失败)
                          返回 401/403
```

### 5.2 安全防护层

| 层 | 防护 | 模块 |
|----|------|------|
| XSS | 输入清理（XssFilter） | common-security + starter-web |
| CSRF | Token 校验 | 业务层自行实现 |
| SQL 注入 | MyBatis-Plus 参数化 + DataScope 校验 | starter-mybatis |
| 签名验证 | 请求签名 + 时间戳校验 | common-security |
| 敏感数据 | 日志脱敏 + 加密存储 | common-security |
| 限流 | Sentinel / 自定义 @RateLimit | starter-sentinel / starter-redis |

## 六、配置管理架构

### 6.1 配置前缀规范

```
sloth.{module}.{sub-module}.{property}
```

| 模块 | 前缀 | 示例 |
|------|------|------|
| Web | `sloth.web` | `sloth.web.response-wrapper.enabled` |
| Auth | `sloth.auth` | `sloth.auth.token-name` |
| Redis | `sloth.redis` | `sloth.redis.key-prefix` |
| MyBatis | `sloth.mybatis` | `sloth.mybatis.tenant.enabled` |
| AI | `sloth.ai` | `sloth.ai.model` |
| Log | `sloth.log` | `sloth.log.print-request-log` |
| ... | `sloth.{module}` | ... |

### 6.2 配置元数据自治

每个 starter **必须**在自己的 `META-INF/` 下维护 `spring-configuration-metadata-additional.json`。

**禁止**在 common-core 中集中管理所有 starter 的配置元数据。
