## 阶段详细说明

### 阶段一：规范先行（Day 1-5）

**目标**：制定所有统一规范文档，作为后续改造的基准。

**原则**：
- 文档先行，代码后动
- 每个规范必须包含"检查方法"（自动化脚本/规则）
- 规范从现有最佳实践提炼，不做空中楼阁

**Day 1 - 统一代码结构与包命名规范**
- 目标：输出完整的包结构规范、命名规范、模块结构规范
- 产出：`02-统一规范/代码结构与包命名规范.md`
- 验收：规范文档完整、包含检查脚本

**Day 2 - 统一日志规范体系**
- 目标：输出日志字段规范、级别规范、格式规范、脱敏规范
- 基于现有 `GlobalExceptionHandler`、`RequestLogFilter` 的最佳实践
- 产出：`02-统一规范/日志规范.md`
- 验收：规范文档完整、与当前代码无冲突

**Day 3 - 统一注释规范与文档规范**
- 目标：类注释/方法注释/字段注释/package-info 规范、README 模板、API 文档规范
- 产出：`02-统一规范/注释与文档规范.md`
- 验收：规范文档完整

**Day 4 - 统一 DTO/VO/Entity 边界与异常规范**
- 目标：DTO/VO/Entity/Query 使用规则、ErrorCode 分配规范、异常处理规范
- 产出：`02-统一规范/模型与异常规范.md`
- 验收：规范文档完整

**Day 5 - 统一测试规范与提交规范**
- 目标：单元测试编写规范、集成测试规范、提交信息规范、PR 规范
- 产出：`02-统一规范/测试与提交规范.md`
- 验收：规范文档完整

### 阶段二：日志体系重构（Day 6-10）

**目标**：消除日志重复、统一日志架构、增强可观测性。

**Day 6 - 日志体系架构设计**
- 确定最终方案：日志分类、模块归属、API 设计
- 确定是保留 `common-log` 还是新建 `starter-logging`
- 风险：方案选择影响后续所有日志相关改造

**Day 7 - 消除重复请求日志**
- `RequestLogFilter`（common-log）与 `AccessLogEvent`（starter-web）的职责重新划分
- 方案：common-log 负责请求日志记录，starter-web 的 AccessLogEvent 删除或只保留事件发布
- 验证：请求只被记录一次

**Day 8 - 统一 MDC + 结构化日志**
- 确保所有 Filter/Interceptor 正确设置 MDC 字段
- Gateway 的 Reactive MDC 方案
- 结构化日志 Encoder 选型

**Day 9 - 慢操作日志统一**
- 定义 `SlowOperationEvent`（操作类型、阈值、实际耗时、上下文）
- starter-mybatis 的 `SlowSqlInterceptor` 发布事件
- starter-es 的 `EsSlowQueryLogger` 发布事件
- starter-monitor 的 `HttpMetricsFilter` 发布事件
- 统一慢操作阈值配置

**Day 10 - 审计日志增强**
- `@OperateLog` 请求参数/响应结果敏感字段自动脱敏
- `OperateLogListener` 支持 `@Async` 异步持久化
- 修复 `operatorLocation` 死代码

### 阶段三：common 层重构（Day 11-15）

**目标**：剥离业务逻辑、治理配置元数据、优化依赖。

**Day 11 - 配置元数据分拆**
- 从 `common-core/META-INF/additional-spring-configuration-metadata.json` 中提取每个 starter 的配置定义
- 放到各自 starter 的 `META-INF/` 下
- common-core 只保留 `sloth.i18n.*` 相关配置
- 影响范围：所有 20+ starter

**Day 12 - 业务逻辑剥离**
- `CacheConstant` 中的业务缓存前缀 → 各 starter 自行定义
- `DataScope` + `DataScopeEnum` → 迁移到 `starter-mybatis`
- `GenderEnum` → 删除（业务枚举）
- `IdempotentType` → 迁移到 `starter-idempotent`

**Day 13 - SecurityUtil 迁移**
- `common-core/util/SecurityUtil.java` → 迁移到 `common-security/crypto/HashUtil`（合并）
- common-core 的安全工具类清零

**Day 14 - Guava 依赖优化**
- 评估 common-core 对 Guava 的实际使用
- 如果无直接使用，改为 `<optional>true</optional>`
- 清理传递依赖

**Day 15 - common 层全量验证**
- `mvn clean verify` 通过
- Checkstyle + SpotBugs 零违规
- 所有 common 模块测试通过
- 下游 starter 编译通过

### 阶段四：starter 层治理（Day 16-21）

**目标**：修复条件装配、解耦重复功能、标准化健康检查。

**Day 16 - 幂等解耦 + 幂等存储 SPI**
- 删除 `starter-redis` 中的 `IdempotentAspect`
- `starter-idempotent` 成为唯一的幂等能力提供者
- 设计 `IdempotentStore` SPI 接口 + `RedisIdempotentStore` 实现
- 设计 `IdempotentKeyStrategy` SPI 接口 + `DefaultIdempotentKeyStrategy`
- 新增 `IdempotentMetrics`（计数器: lock acquired/rejected/timeout, token created/consumed/rejected）
- 新增 `IdempotentRejectedEvent`（拒绝事件）

**Day 17 - OSS 条件装配 + starter-sms 真实 SDK 集成**
- `OssAutoConfiguration` 增加 `@ConditionalOnClass` 守卫
- **重写 `AliyunSmsClient`**（真实 SDK: `com.aliyun:dysmsapi20170525`）
- **重写 `TencentSmsClient`**（真实 SDK: `com.tencentcloudapi:tencentcloud-sdk-java-sms`）
- `SmsAutoConfiguration` 增加 `@ConditionalOnClass` 守卫
- 新增 `SmsHealthIndicator`, `SmsMetrics`, `SmsSentEvent/SmsFailedEvent`
- 参见: `05-starter层升级/starter-sms增强方案.md`

**Day 18 - MyBatis 修复 + starter-job 增强**
- `MybatisPlusAutoConfiguration` 增加 `@ConditionalOnClass`
- `isDevProfile()` 默认返回 `false`（安全优先）
- **starter-job 增强**：
  - 新增 `JobExecutionEvent`（执行事件）
  - 新增 `JobInterceptor` / `JobInterceptorChain`（执行拦截器 SPI）
  - 新增 `JobMetrics`（指标: execution total/success/failure/duration）
  - 新增 `JobHealthIndicator`（Admin 连通性检查）
  - 新增 `RetryableJob` 注解 + `RetryableJobHandler`（重试支持）
  - 参见: `05-starter层升级/starter-job增强方案.md`

**Day 19 - Monitor 清理 + starter-seata 增强**
- 移除 `monitorActuatorExposurePostProcessor` BeanPostProcessor
- 改为文档引导用户自行配置
- **starter-seata 增强**：
  - 新增 `SeataTracingFilter`（xid → MDC 桥接）
  - 新增 `GlobalTransactionEvent` + `SeataTransactionEventListener`（事务事件）
  - 新增 `SeataHealthIndicator`（TC 连接状态检查）
  - 新增 `SeataMetrics`（transaction total/commit/rollback/duration）
  - 新增 `SeataCustomizer` SPI（扩展点）
  - 参见: `05-starter层升级/starter-seata增强方案.md`

**Day 20 - Gateway MDC + starter-sentinel 增强**
- 实现 Reactive MDC Context Propagation
- **starter-sentinel 增强**：
  - 新增 `SentinelHealthIndicator`（初始化状态、数据源连通性）
  - 新增 `SentinelMetrics`（Micrometer 桥接: block/pass/exception count, rt）
  - 新增 `ReactiveSentinelBlockExceptionHandler`（WebFlux 支持）
  - 新增 `DataSourceConfigStrategy` + `FileDataSourceConfig`（多数据源支持）
  - 新增 `SentinelTransportConfig`（Dashboard 连接配置）
  - 参见: `05-starter层升级/starter-sentinel增强方案.md`

**Day 21 - starter-feign 增强 + 全量验证**
- **starter-feign 增强**：
  - 新增 `FeignMetricsInterceptor`（调用指标: total/duration/error）
  - 新增 `OkHttpConnectionPoolMetrics`（连接池指标）
  - 新增 `FeignHealthIndicator`（下游服务可达性检查）
  - 新增 `FeignRetryer`（可配置重试策略）
  - 新增 `FeignBodyLoggingFilter`（请求体 DEBUG 日志）
  - 新增 `SentinelFeignAutoConfiguration`（熔断集成）
  - 参见: `05-starter层升级/starter-feign增强方案.md`
- **全量验证**：全部 18 个 starter 编译通过、条件装配正确、事件解耦验证
